# AGENTS.md

Guidance for coding agents and humans working on FXStream Web.

## Project overview

A Vite + React + TypeScript SPA for live FX/crypto rates, candles, and expiring quotes. It talks to
the FXStream REST and WebSocket API. Development defaults to MSW fixtures so the UI runs without a
backend.

## Setup

```bash
mise install
bun install
cp .env.example .env.local
bun run dev
```

The local `.mise.toml` pins Node 24 and Bun 1.4.3. Do not assume global versions.

## Architecture

- `src/app/` — providers, router, layout, route pages, runtime configuration.
- `src/features/rates/` — snapshot query, live Zustand store, socket hook/provider, rates table.
- `src/features/chart/` — candle query, `lightweight-charts` wrapper, interval selector.
- `src/features/quotes/` — quote mutation, form, countdown, quote card.
- `src/features/status/` — provider health and connection diagnostics.
- `src/lib/` — API client, WebSocket state machine, formatting, clock utilities.
- `src/test/` — test setup, MSW fixtures, scenario switches.

Presentational components receive data through props. Hooks/containers own fetching and side
effects. Keep REST data in TanStack Query, live ticks in Zustand, and quote state local.

## Conventions

### TypeScript and React

- Strict TypeScript. Avoid `any`; use discriminated unions and explicit guards.
- Use function components and hooks. Follow the existing named-export style.
- Keep components presentational where practical; put data access in hooks.
- Use the `@/` path alias for imports from `src/`.
- Avoid unnecessary `useEffect` state synchronization. Prefer derived state, keys, or external
  stores. React's lint rules flag setState-in-effect and impure render calls.

### Data and numbers

- Prices are strings end to end. Never store or calculate business prices as floats.
- Use `src/lib/format/decimal.ts` for decimal-safe arithmetic and `price.ts` for display.
- `lightweight-charts` needs numbers; convert only at the chart boundary.
- `Intl.NumberFormat` handles grouping; pair precision comes from config or the API.
- Timestamps are ISO strings in the contract. Display local time and expose UTC in `title`.

### WebSocket client

- One app-wide connection via `RatesSocketProvider`.
- Reconnect with exponential backoff and jitter.
- Resubscribe all active symbols on reconnect; diff subscriptions while open.
- Keep the heartbeat watchdog; do not remove the no-message fallback without adding a real
  server heartbeat.
- Ignore unknown message types through the discriminated union in `lib/ws/protocol.ts`.

### Mocks

- MSW handlers live in `src/test/mocks/`.
- Scenarios are selected with `?scenario=normal|stale|degraded|offline|quote-rejected|fast-expiry`.
- Keep fixtures deterministic and prices as strings.
- Browser worker: `src/test/mocks/browser.ts`; Node tests: `src/test/mocks/server.ts`.
- `public/mockServiceWorker.js` is generated by `bunx msw init public --save`; do not hand-edit it.

### Testing

- Co-locate unit tests as `*.test.ts(x)`.
- Use Testing Library and MSW; avoid testing implementation details.
- Use fake timers for countdown/reconnect tests and reset stores/clock/mocks between tests.
- Playwright specs live in `e2e/`; run against mock mode.
- E2E coverage should include stale, offline, rejected quote, and expiry scenarios.

### Styling

- Tailwind CSS v4 with tokens declared in `src/styles/index.css`.
- Dark-only UI. Use the shared UI primitives in `src/components/ui/`.
- Preserve accessible labels, table semantics, focus states, and `aria-live` regions.
- Do not encode status with color alone; pair colors with text/badges.

### Configuration and secrets

- All browser-exposed variables start with `VITE_` and are public. Never put secrets in them.
- Add new env vars to `.env.example`, the config module, and `vite-env.d.ts`.
- Default symbols and interval belong in config, not components.
- Real backend integration is environment-only: `VITE_USE_MOCK_API=false` plus the two URLs.

### API types

- Interim domain types live in feature folders and follow `docs/frontend-design.md`.
- When the backend exposes the FX OpenAPI schema, generate types with `bun run generate:api` and
  adapt the client. Keep the single fetch wrapper as the only place that knows the base URL.
- Backend error envelope: `{ "error": { "code", "message", "details"? } }`. Surface `message` to the
  user and retain the code for handling.

## Do not

- Do not bypass the API client or hardcode URL paths in components.
- Do not introduce a global store for snapshot, candles, or quote state.
- Do not use floats for price arithmetic.
- Do not hide degraded/offline states or silently ignore unknown WebSocket messages.
- Do not commit generated coverage, Playwright reports, or local env files.
- Do not weaken strict TypeScript or lint rules to make a change pass.
